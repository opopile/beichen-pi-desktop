# 北辰 Pi 1.8.2 完整使用说明

> English version: [Beichen Pi 1.8.2 Complete User Guide](USER_GUIDE_EN.md)

> 北辰 Pi 是独立、非官方的第三方开源项目，与所支持的模型服务商不存在隶属、合作或官方背书关系。
>
> Agent 模式不是安全沙箱：它能够以当前 Windows 用户权限执行 PowerShell、读取和修改工作目录文件并加载 Pi 扩展。只打开可信项目，重要数据先使用 Git 和离线备份保护。

> 适用平台：Windows 10/11 x64
> 当前内核：Electron 44 + Pi 0.84.4 RPC
> 文档版本：1.8.2

## 1. 产品概览

北辰 Pi 是一个将 Pi 编程代理包装为 Windows 桌面应用的图形客户端。它同时提供普通对话与项目执行能力，并保留 Pi 的模型、会话、工具、技能、扩展、上下文压缩和认证系统。

核心能力：

- ChatGPT 与 Codex 两种工作界面。
- 每个窗口独立运行一个 Pi RPC 进程。
- 内置 API Key、会员订阅 OAuth、自定义 API 和无密钥本地模型接入。
- 每个窗口独立选择服务商、模型、推理强度和工作目录。
- 安装版与免安装便携版。
- 七套界面主题与中英文切换。
- 实时 token/s 与上下文占用圆环。
- Pi 会话、技能、扩展和提示模板支持。
- 五档可见 Codex 性能模式；Extreme 实现暂时隐藏。
- 图片附件、流式回复、停止任务和错误提示。

## 2. 下载版本

构建产物位于项目的 `release` 目录：

- `Beichen-Pi-Setup-1.8.2-x64.exe`：安装版。
- `Beichen-Pi-Portable-1.8.2-x64.exe`：模型和推理均使用应用自绘右侧子菜单的免安装便携版，同时保留独立圆环仪表、左上角上下文滑块、完整实时思考和大括号压缩/删除视图。

### 2.1 安装版

适合日常长期使用。安装向导允许选择目录，并可创建桌面和开始菜单快捷方式。

### 2.2 便携版

无需安装，双击即可启动。首次运行时会解压到 Windows 临时目录，因此第一次启动可能比安装版稍慢。

### 2.3 SmartScreen 提示

当前构建没有购买商业代码签名证书，Windows 可能显示“未知发布者”或 SmartScreen 提示。请确认文件来自本项目的 `release` 目录并核对 SHA-256 后再运行。

## 3. 系统要求

- Windows 10 或 Windows 11，x64 架构。
- 建议 8 GB 以上内存。
- 至少 500 MB 可用磁盘空间。
- 使用云模型时需要网络连接。
- 目标电脑不需要预装 Node.js；应用已经内置 Node 24 运行时。
- 云模型调用需要有效的 API Key 或受支持的会员订阅；本地模型服务可使用无密钥模式。

## 4. 首次启动

1. 运行安装版或便携版。
2. 应用自动读取 Pi 的全局配置目录。
3. 默认打开上次使用的工作目录；无记录时使用启动目录或“文档”目录。
4. 顶部模型状态点变为绿色后，Pi RPC 已就绪。
5. 如果模型没有凭据，进入“设置 → 模型与接入”完成配置。
6. 顶部紫色北辰星的推广动画每个应用版本只展示一次。

## 5. 主界面说明

### 5.1 自定义标题栏

标题栏包含：

- 北辰 Pi 图标与程序名。
- 顶部中央紫色北辰星。
- 最小化、最大化和关闭按钮。

窗口空白区域可拖动。按钮区域不会触发窗口拖动。

### 5.2 左侧边栏

边栏包含：

- **新任务**：在当前窗口创建空白 Pi 会话。
- **搜索任务**：按标题或工作目录过滤历史会话。
- **插件与技能**：打开插件、技能和提示模板列表。
- **性能实验室**：打开 Codex 性能模式设置。
- **工作区**：显示和切换当前工作目录。
- **任务列表**：显示 Pi 已保存的会话。
- **新窗口**：创建独立窗口和独立 Pi 进程。
- **设置**：打开右侧设置界面。

点击边栏顶部图标可收起或展开边栏。收起后，侧栏宽度与边框都会归零，工作区扩展到整个窗口宽度；聊天内容、输入框和底部 Token 状态行会一起向左重新居中，不会留下透明占位。

任务搜索框会跟随当前主题。水墨、温柔猫娘、奶油治愈等浅色主题会同步调整搜索框底色、边框、文字、占位文字、焦点与自动填充状态；切换主题后无需重启。

### 5.3 顶部工作栏

顶部工作栏包含：

- ChatGPT/Codex 模式切换。
- Codex 性能模式入口。
- 当前模型、服务商状态和推理等级。
- 中文/英文切换。
- 主题快捷切换按钮。
- 新建窗口按钮。

### 5.4 会话区

会话区显示：

- 用户消息。
- 模型回复和 Markdown 内容。
- 代码块、表格、列表与链接。
- 可展开的思考摘要。
- 工具调用和执行状态。
- 模型错误卡片。

Ultra Max、Quantum Collapse 和 Ghost Payload 会隐藏执行过程中的中间文本，任务结束后再显示最终结果。

所有模式都实时展示服务商通过 Pi 返回的完整 thinking。静默模式只隐藏进度文字和工具时间线，不再隐藏 thinking。

### 5.4.1 完整思考与模型实际上下文

- thinking 面板默认展开，并通过 `thinking_delta` 实时增长；可以手动收起。
- Quantum/Ghost 当前工具循环尚未结束时只显示“实时”，不会提前宣称已经压缩或删除。
- Quantum 回合完成后，完整 thinking 右边出现纵向大括号和“已压缩”卡片；卡片逐字显示下一轮实际使用的本地 digest。
- Ghost 回合完成后，完整 thinking 右边出现大括号和“已删除”卡片；完整原文仍保存在本地供用户查看，但不会回灌模型。
- 多次工具调用产生的每段 assistant thinking 都保留展示，静默模式只隐藏其中的进度正文。
- 该视图仅展示服务商真实返回的 thinking；服务商未提供时显示为空，不会推测或伪造。

### 5.5 输入区

输入区支持：

- 普通文本。
- `Shift + Enter` 换行。
- `Enter` 发送。
- 最多四张图片附件。
- 切换工作目录。
- 流式执行期间停止任务。
- 在聊天栏下方直接切换当前窗口的模型。
- 在 ChatGPT 与全部 Codex 性能模式中自由切换当前模型支持的思考强度。
- 显示当前性能模式、实际生效推理等级、token/s 和上下文圆环。

模型和思考不再占用两个并排小下拉框：点击单一胶囊后，弹层只显示“模型、推理强度”两项。

1.8.1 中两项都不再调用 Windows/Chromium 原生下拉框。悬停或点击主菜单行会在右侧展开应用自绘的圆角子菜单；当前模型或思考档位带勾选，模型名称和服务商分层显示，长列表仅在子菜单内部滚动。

Token 仪表保持原来的小圆环入口。Codex 上下文模式在左上角模式按钮中独立切换：CODEX/BENCHMARK 使用蓝色轨道；进入 ULTRA MAX、QUANTUM COLLAPSE、GHOST PAYLOAD 后切换为紫色渐变、星点和白色大滑块。聊天栏胶囊始终显示“模型 + 推理强度”。

### 5.6 输入与链接安全

- 中文输入法正在组合拼音时，`Enter` 只用于选词，不会发送消息；组合结束后 Enter 才发送。
- 删除图片预览后可以再次选择同一文件，文件输入值会在每次选择后清空。
- 流式输出仅在视图接近底部时自动跟随；用户上翻历史后不会被强制拉回底部。
- Markdown 外链不会在 Electron 内创建新窗口。应用仅把 `http`、`https` 和 `mailto` 交给系统默认程序；`file`、`javascript`、`data` 和未知协议一律阻止。

## 6. ChatGPT 与 Codex 模式

### 6.1 ChatGPT 模式

适合问答、解释、写作、分析和创意任务。

特点：

- 不加载 Pi 的内置文件修改工具。
- 使用通用对话提示词。
- 不会直接修改项目文件。

### 6.2 Codex 模式

适合读取项目、修改代码、执行命令、测试和交付完整功能。

默认可用工具：

- `read`
- `powershell`
- `edit`
- `write`
- `grep`
- `find`
- `ls`

Codex 模式还会加载 Pi 的项目上下文、技能与扩展。

## 7. 工作目录

工作目录决定：

- Pi 工具执行位置。
- 项目级 `.pi`、`.agents` 和说明文件发现范围。
- 会话保存目录分组。
- 文件读写的默认根目录。

切换方法：

1. 点击左侧工作区卡片；或
2. 点击输入区左下角的目录按钮；或
3. 进入“设置 → 通用”。

切换工作目录会重启当前窗口的 Pi RPC，不会影响其他窗口。

## 8. 会话与历史记录

Pi 会话保存在：

```text
%USERPROFILE%\.pi\agent\sessions
```

功能包括：

- 新建会话。
- 从边栏恢复历史会话。
- 保存模型、推理等级、消息与工具结果。
- 支持 Pi 的会话树、分支和压缩记录。

应用的自动化测试可能生成以测试文本命名的会话；可在 Pi 会话目录中自行归档或删除。

## 9. 模型与接入

进入“设置 → 模型与接入”。

### 9.1 会员订阅

切换到“会员订阅”后，会显示支持 OAuth 的服务商，例如：

- OpenAI Codex（ChatGPT Plus/Pro）
- Anthropic
- GitHub Copilot
- xAI
- 其他由 Pi 支持的订阅服务

点击“连接订阅”，按照浏览器授权流程完成登录。

### 9.2 API Key

切换到“API”后，可选择 Pi 支持的 API 服务商。点击“配置 API Key”，在安全输入框中填写密钥。

API Key 不会写入聊天记录；凭据由 Pi 认证存储管理。

认证提示提供“取消”按钮。取消会终止当前认证输入；关闭对应窗口时，属于该窗口的待处理认证 Promise 也会被拒绝和清理。

### 9.3 选择模型

最直接的方法是在聊天输入框下方点击“模型”下拉框。模型在当前 Pi 会话内即时切换，不重启 RPC、不清空消息，也不影响其他窗口。

也可从设置选择：

1. 选择服务商。
2. 确认服务商状态为“已连接”。
3. 从模型下拉框选择模型。
4. 点击“应用到当前窗口”。

应用会保留当前会话并即时切换模型。其他窗口的模型不会改变。新模型不支持原思考档位时，Pi 会回落到可用档位，界面显示的是实际生效值。

### 9.4 自由切换思考强度

聊天输入框下方的“思考强度”下拉框来自 Pi `get_available_thinking_levels`，因此只显示当前模型真实支持的档位：

- `Off`：关闭额外推理。
- `Minimal`：极低推理。
- `Low`：低推理。
- `Medium`：中等推理。
- `High`：高推理。
- `Extra high`：超高推理，对应 `xhigh`。
- `Max`：当前模型公开支持的最大推理档。

不同模型提供的列表可能不同；非推理模型通常只显示 `Off`。切换后无需重启，当前窗口和会话立即采用新档位。每个窗口独立保存选择。

模型、思考强度和性能模式是三项独立控制：

- 模型决定能力、上下文上限、价格和可用思考档位。
- 思考强度决定该模型本次工作使用的推理力度。
- 性能模式决定进度是否显示、验证倾向、工具策略与上下文策略。

切换 ChatGPT/Codex、切换任何性能模式、触发纯问候轻量路由或更改工作目录，都不会覆盖手动选择的思考强度。

### 9.5 自定义 API 接入

进入“设置 → 模型与接入”，滚动到“自定义 API”，点击“添加自定义 API”。保存后该模型立即应用到当前窗口，也会出现在聊天栏下方的模型列表中。

应用内置了“快速接入”预设（例如 Baimeow 中转 · Kimi K3 Max）：点击预设按钮后，地址与模型会自动填好，只需粘贴 API Key 并点击“保存并应用”。已保存相同地址与模型的预设会自动隐藏。

基础字段：

- **接入名称**：只用于界面识别，例如“公司网关”或“本地 Ollama”。
- **API 基础地址**：填写服务根地址，例如 `https://api.example.com/v1` 或 `http://127.0.0.1:11434/v1`，不要填写账号、密钥或单独的 `/chat/completions` 路径。
- **接口协议**：支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Generative AI。
- **模型 ID**：接口实际接收的模型标识，必须与服务端一致。
- **显示名称**：界面中显示的友好名称；留空时使用模型 ID。
- **API Key**：需要认证时填写；Ollama、LM Studio、vLLM 等无密钥本地服务可勾选“本地服务无需密钥”。

“模型能力与兼容性”高级设置：

- 上下文上限与最大输出 Token。
- 是否支持 reasoning、图片输入以及 `Extra High / Max`。
- 思考参数格式：自动、OpenAI `reasoning_effort`、OpenRouter、DeepSeek 或 Qwen。
- 是否支持 `developer` role。
- 是否需要强制添加 `Authorization: Bearer`。

保存行为：

1. 应用验证 URL、模型 ID 和 Token 上限。
2. API Key 使用 Electron `safeStorage` 和 Windows 系统凭据加密为密文。
3. 应用将模型合并到 Pi 原生 `%USERPROFILE%\.pi\agent\models.json`；不会覆盖用户已有服务商。
4. `models.json` 只保存 `$BEICHEN_CUSTOM_API_...` 环境变量引用，不保存 API Key 明文。
5. 所有窗口刷新 Pi 模型目录，当前窗口自动切换到新模型；其他窗口继续保留各自模型选择。

编辑已有接入时，API Key 留空会保留原加密密钥。删除接入时，正在使用该服务的窗口会回到保存接入前的模型。删除前应用会要求确认。

自定义 API 沿用 Pi 原生模型层，因此仍支持工具调用、会话、Token 仪表、自由思考强度和所有性能模式。实际能力取决于服务端是否正确实现所选协议；保存配置不会发送测试聊天或消耗模型 Token，第一次对话才会验证网络与密钥是否可用。

### 9.6 常见模型状态

- 绿色圆点：Pi 后端与模型目录已就绪。
- 黄色圆点：正在启动或刷新。
- 红色圆点：Pi 进程、凭据或模型加载失败。

## 10. 多窗口与软件多开

点击“新窗口”会在同一应用进程中创建新的 BrowserWindow，并为该窗口创建独立 Pi RPC。

每个窗口可独立设置：

- 工作目录。
- ChatGPT/Codex 模式。
- 模型和服务商。
- 推理等级与性能模式。
- 当前会话。

也可以重复运行 EXE，创建多个应用实例。

## 11. Codex 性能模式

将鼠标移到顶部 Codex 性能按钮，或进入“设置 → 性能模式”。

| 模式 | 思考强度 | 输出策略 | 上下文策略 | 适用场景 |
| --- | --- | --- | --- | --- |
| CODEX | 自由选择 | 稀疏显示有效进度 | 精简 Pi 提示 + Pi 默认压缩 | 日常项目开发 |
| BENCHMARK | 自由选择，跑分建议 Max | 跑分证据可见 | 真实指标、基线、瓶颈与严苛验证 | 跑分、评测、极限优化 |
| ULTRA MAX | 自由选择且完整执行 | 运行中静默，结束后只显示最终回答 | 精简 Pi 提示 + Pi 默认压缩 | 无人值守复杂任务 |
| QUANTUM COLLAPSE | 自由选择且完整执行 | 与 Ultra Max 相同 | 已完成 thinking 压缩摘要 + Pi 默认压缩 | 长会话、保留推理线索 |
| GHOST PAYLOAD | 自由选择且完整执行 | 与 Ultra Max 相同 | 已完成 thinking 剔除 + Pi 默认压缩 | 最小化后续上下文载荷 |

所有性能模式都不会强制或重置思考强度。若手动选择的档位不受新模型支持，Pi 按模型能力回落，应用读取并显示实际生效档位。

`EXTREME EFFICIENCY` 的实现暂时保留但不再出现在滑块、性能设置或使用说明中。旧设置若仍指向该档，启动时自动回落到 CODEX。

### 11.1 设置内置模式说明

设置左侧最后一项为“使用说明”。右侧内置说明包含：

- ChatGPT/Codex 与五个可见性能模式的快速对比表。
- 每个模式的独立思考选择、过程可见性、工具和压缩行为。
- 适合与不适合的任务类型。
- 延迟、费用、上下文和可观察性权衡。
- 何时应该切换到另一模式。
- Quantum 回合后 thinking 压缩和 Ghost Payload 回合后 thinking 剔除的真实边界。

详细模式使用说明以可展开分组显示，不会改变当前模式；实际切换仍在顶栏性能按钮或“设置 → 性能模式”中完成。

### 11.2 回合后处理的统一规则

Quantum Collapse 和 Ghost Payload 都遵守同一条生命周期边界：

1. 当前回合按用户选择的思考强度完整运行。
2. 模型正常调用工具、验证并产出最终结果。
3. 只有下一次请求准备模型上下文时，才处理已经完成回合的 thinking。
4. 当前工具循环和其签名始终原样保留。
5. Pi 原生自动压缩始终启用；模式处理是额外叠加层，不会调用或替换整段 `compact`。

因此“压缩/剔除 thinking”不等于不让模型思考，也不影响已经完成回合的质量和 reasoning token 计费。

### 11.3 Quantum Collapse 的边界

Quantum 在 Ultra Max 之上增加本地、回合后思考压缩：

- 已完成 thinking 被提取成最多约 480 字符的 `<reasoning_digest>`。
- 摘要优先保留开端、结论、根因、验证和下一步。
- 用户消息、最终回复与工具证据保持原样。
- 不发起额外模型请求，因此没有额外摘要调用费用和等待。
- 保存到磁盘的原始会话不被改写；只改变后续发送给模型的临时上下文。

### 11.4 Ghost Payload 的边界

Ghost Payload 只改变后续请求携带的上下文：

- 删除已完成回合的思考块。
- 保留当前工具循环所需的签名。
- 保留最终回复、工具证据和用户消息。
- 继续保留 Pi 原生自动压缩。

它不会让服务商已经生成的 token 免费，也不会突破服务商上下文或计费规则。

## 14. Token 速率

输入框下方显示 `tok/s`。

计算方式：

1. 流式阶段根据文本增量实时估算 token 数。
2. 收到最终 assistant usage 后，使用真实输出 token 数校正。
3. 速率为输出 token 数除以本轮运行时间。

工具执行、网络等待和静默推理会降低显示的平均速率。这是完整运行速率，不等同于服务商公布的纯解码峰值。

### 14.1 打开完整 Token 仪表

软件底部始终显示一条独立 Token 状态行，包含上下文圆环、模型、已用、上限、剩余和实时速率。点击状态行或右侧箭头，软件底部会向上展开“Token 完整仪表”；再次点击即可收起。

仪表展开后：

- 输入框整体上移。
- 会话区自动增加底部留白。
- 仪表成为软件布局中的独立底部区域，不覆盖输入框或会话内容。
- 不再依赖鼠标悬停，因此触控板、触屏和不同 DPI 设置下也能稳定打开。

### 14.2 上下文容量区

顶部大圆环和容量条显示：

- 上下文已用 token。
- 上下文剩余 token。
- 模型上下文上限。
- 已用百分比；低于 1% 时保留两位小数。
- 模型最大输出 token。
- 图形化圆环进度。
- 已用/剩余容量条和当前位置标记。

### 14.3 会话累计 Token

会话累计区使用 Pi `get_session_stats`，包括：

- 输入 token。
- 输出 token。
- 缓存读取 token。
- 缓存写入 token。
- 总 token。
- 缓存命中率。
- 累计费用。
- 彩色堆叠比例图。

会话累计包含助手消息、工具内部模型调用、上下文压缩和分支摘要，因此可能大于当前可见消息之和。

### 14.4 最近一次模型回复

如果服务商返回完整 usage，会显示：

- 输入 token。
- 输出 token。
- 推理 token。
- 缓存读取和缓存写入。
- Anthropic 可能提供的 1 小时缓存写入。
- 总 token。
- 缓存命中率。
- 本次总费用。
- 输入、输出、缓存读取和缓存写入的费用拆分。

推理 token 是输出 token 的子集，不能再次相加。服务商未返回 reasoning 时显示“—”。

### 14.5 当前运行图表

当前运行区显示：

- 实时 token/s。
- 当前已输出 token。
- 已运行秒数。
- 最近约 40 个速率样本的折线/面积图。
- 数据来源：流式本地估算或服务商实际返回。
- 自动压缩状态。
- 当前推理等级。

### 14.6 消息与工具统计

活动区显示：

- 用户消息数量。
- 助手消息数量。
- 工具调用数量。
- 工具结果数量。
- 消息总数。
- 会话 ID 缩写。

### 14.7 数据精度与不可用值

- `SessionStats` 和最终 usage 优先作为权威数据。
- 流式过程中服务商尚未返回 usage，因此 token/s 使用本地估算。
- 完成回复后使用真实输出 token 校正速率。
- 上下文 token 是 Pi 用于压缩判断的当前估算。
- 压缩后、下一次回复前，上下文 token 和百分比可能为“—”。
- 订阅服务商可能不提供货币费用。
- 某些模型不提供推理 token、缓存写入或缓存读取明细。
- 不可获得的字段显示“—”，不会以 0 或其他估算冒充。

## 15. 上下文圆环

圆环使用 Pi `get_session_stats` 返回的真实上下文统计。

- 圆环中央数字：当前上下文占用百分比；低占用时保留小数。
- 圆环进度：上下文窗口占用比例。
- 点击圆环所在的底部状态行：展开或收起完整 Token 仪表。
- `0` 或空心：新会话或尚未获得有效 usage。
- 压缩后暂时为空：需要下一次模型回复生成新的有效统计。

## 16. 插件、技能与提示模板

进入“设置 → 插件与技能”。列表通过 Pi RPC 的 `get_commands` 实时获取。

来源类型：

- `extension`：Pi 扩展命令。
- `skill`：技能，命令以 `/skill:` 开头。
- `prompt`：提示模板。

点击条目会把斜杠命令插入输入框，不会立即发送。

```text

```

添加或修改资源后，重启窗口以确保完整加载。

## 17. 图片附件

1. 点击输入框左下角回形针。
2. 选择 PNG、JPG、WebP 等图片。
3. 每次最多附加四张。
4. 点击缩略图右上角关闭按钮可移除。

## 18. 上下文压缩

Pi 在上下文接近上限时自动压缩历史消息。

压缩会保留：

- 用户目标。
- 硬性约束。
- 已完成工作。
- 修改和读取的文件。
- 验证结果。
- 阻塞项和下一步。

Quantum Collapse 和 Ghost Payload 不会替代上述自动压缩。它们只在下一次模型请求前处理已完成回合的 thinking：Quantum 生成本地短摘要，Ghost 直接剔除；当前回合 thinking 与工具循环不受影响。

## 19. 凭据、隐私与本地数据

Pi 默认配置目录：

```text
%USERPROFILE%\.pi\agent
```

常见文件：

- `settings.json`：Pi 默认模型与界面设置。
- `auth.json`：API/OAuth 凭据。
- `models-store.json`：模型目录缓存。
- `sessions/`：会话历史。
- `skills/`：全局技能。
- `extensions/`：全局扩展。

安全建议：

- 不要把 `auth.json` 上传到公共仓库。
- 不要在聊天中粘贴完整 API Key。
- 定期检查服务商用量和费用。
- 备份会话时单独处理凭据文件。
- 主题和语言保存在 Electron 本地存储中。

## 20. 错误提示与排错

### 20.1 401 认证失败

原因：API Key 无效、过期或 OAuth 登录失效。

处理：

1. 打开“设置 → 模型与接入”。
2. 断开服务商。
3. 重新配置 API Key 或连接订阅。

### 20.2 403 权限被拒绝

原因：API 项目没有模型权限，或服务商拒绝当前项目。

处理：切换有权限的项目、会员订阅或其他服务商。

### 20.3 404 模型不可用

原因：模型被下线、更名，或当前账户不可见。

处理：刷新模型目录并切换到服务商当前支持的模型。

### 20.4 429 配额或限流

原因：余额不足、免费配额为零、每分钟/每日限制或服务繁忙。

处理：

- 稍后重试。
- 切换模型。
- 检查账单与配额。
- 改用其他 API 或会员订阅。

### 20.5 红色后端状态点

检查：

- 工作目录是否存在。
- Pi CLI 与内置 Node 是否完整。
- `resources/app.asar.unpacked` 是否包含 Pi 与 `jiti`。
- 凭据是否可用。
- 扩展是否存在语法或依赖错误。

### 20.6 插件列表为空

检查：

- 是否处于 Codex 模式。
- Pi 资源目录是否存在。
- 扩展和技能文件是否有效。
- 切换目录或更新资源后是否重启窗口。

### 20.7 便携版启动慢

便携版首次运行需要解压约百兆运行文件。安装版启动更快，适合日常使用。

### 20.8 新任务没有工具

1. 查看当前后端是否因纯问候进入 Light 路由，或上一回合是否异常中断。
2. 点击“新任务”会自动终止残留流式任务、恢复 `routeTier: full`，再创建新会话。
3. 若仍无工具，切换一次 Codex 模式或重启当前窗口并检查扩展错误提示。

## 22. 卸载

%USERPROFILE%\.pi\agent

## 25. 已知限制

- 应用不能突破模型服务商的权限、余额、配额和上下文限制。
- EXE 未使用商业代码签名证书。
- token/s 在流式阶段是估算值，完成后才会被真实 usage 校正。
- 服务商未返回的推理、缓存或费用字段只能显示为不可用。
- 不同模型对图片、工具、推理等级和上下文持久化的支持不同。
- ChatGPT 模式不加载文件修改工具。
- 主题背景会增加约数 MB 的安装包体积。
